# 显示范围显式应用设计

## 目标

解决长序列报告中拖动双端范围条或连续编辑范围数字时反复重算、重绘 GWAS、基因结构、序列表和 LD 图造成的卡顿。

## 交互设计

- 范围条和起止数字框编辑的是“待应用范围”，只同步端点、数字框、蓝色选区和范围标签。
- 编辑待应用范围时不得调用 `applyFilters()`，页面中已显示的数据保持不变。
- 待应用范围与当前已应用范围不同时，显示“有未应用更改”，并启用“应用范围”按钮。
- 点击“应用范围”后校验并规范化起止值，更新当前过滤范围，随后只调用一次 `applyFilters()`。
- “清除”只把待应用范围重置为完整区域，不立即重绘；用户仍需点击“应用范围”。
- 如果待应用范围与已应用范围相同，“应用范围”按钮禁用且不触发计算。
- 鼠标、触摸和键盘操作遵循同一规则，不在 `pointermove`、`input` 或 `change` 事件中自动计算。

## 状态边界

保留两套独立状态：

- `currentFilter.rangeStart/rangeEnd`：当前已应用、实际用于过滤和重绘的范围。
- 范围控件中的值：待应用范围，只负责交互预览。

同步控件的函数不得隐式覆盖已应用状态。显式提交函数负责从控件读取值并写入 `currentFilter`，从而避免拖动预览污染实际过滤结果。

## 错误和边界处理

- 起止值继续限制在基因区域边界内。
- 起点大于终点时沿用现有的活动端点规则规范化，确保最终范围有效。
- 空值分别按区域起点或终点处理。
- 重合端点仍支持向左拖动选择起点、向右拖动选择终点。
- 取消指针操作只结束拖动，不提交计算。

## 测试与验收

- 自动化测试确认滑块拖动、数字输入和清除操作均不调用 `applyFilters()`。
- 自动化测试确认点击“应用范围”恰好调用一次 `applyFilters()`，并更新 `currentFilter`。
- 自动化测试确认无未应用更改时不会重复计算。
- 保留双端独立拖动、重合端点拆分、越界处理和起止交叉行为测试。
- 重跑 VRN-B1 报告，并在 Chromium 与 Firefox 中验证：拖动期间图表不重绘，点击应用后所有关联视图一次性同步。

## 范围外事项

本次只改变显示范围控件的提交时机，不修改 robust discovery 打分、单倍型划分、文献位点验证或分析结果。
