# 初始显示范围与缩放布局设计

## 目标

让长基因报告首次打开时直接呈现可读的局部窗口，并确保 Zoom 只改变内容密度，不缩小主视图区，也不改变已应用的基因组范围。

## 初始显示范围

- 初始窗口完全由基因结构和变异位置决定，不使用表型、文献功能位点、验证标记或 discovery 排名。
- 当可显示变异数不超过 25 时，初始显示完整范围。
- 当变异数超过 25 时，以基因区间中点为锚点；缺少有效基因坐标时使用报告区域中点。
- 在排序后的变异位置中找到最接近锚点的位置，向两侧选择连续的 25 个变异，并以首末变异坐标作为初始范围。
- 当前 VRN-B1 数据应得到约 `5,447–12,446` 的初始范围，共 25 个变异列。这个结果是位置算法的产物，不针对 837 bp 文献插入。
- 初始范围同时写入 `currentFilter` 和 `pendingRangeFilter`，因此首次加载不显示“未应用更改”。

## 范围操作语义

- 拖动范围条、编辑数字和 Clear 仍只修改 pending 范围，不触发计算。
- Apply Range 直接提交已经规范化的 `pendingRangeFilter`，不得重新解释原始输入框，从而保证预览与提交一致。
- 交叉数字输入示例 `Start=90, End=80` 应按活动端点规则预览为 `80–80`，Apply 后也必须保持 `80–80`。
- Clear 将 pending 范围设为完整区域；点击 Apply 后才显示完整范围。
- Reset 恢复 MAF、缺失率等默认过滤条件，并恢复自动计算的初始 25 位点窗口，而不是完整范围。
- 外部 `postMessage` 范围更新继续视为显式应用，并同步 current/pending 状态。

## Zoom 语义与布局

- 将报告级缩放从 `transform: scale()` 改为现代浏览器支持的 CSS `zoom`。
- 20%–150% 的控件范围保持不变。
- 缩放后主视图区仍占满 `.content-wrapper` 的可视宽度；例如 50% 时外层视口保持约 1008px，而不是缩成约 504px。
- Zoom 不读写 `currentFilter`、`pendingRangeFilter` 或范围输入框，因此不会改变显示的基因组坐标范围。
- 缩放后重新计算基因结构到序列表的连线和 LD 图，保持坐标对齐。
- Print/export 临时使用 100% 布局测量，打印样式显式清除 `zoom`，避免导出尺寸继承交互缩放。
- Fit 使用未缩放内容尺寸计算目标比例，避免当前 zoom 值参与后产生累积误差。

## 初始定位

- 首次应用默认窗口后，将 `.main-data-section` 水平滚动到该范围中心附近。
- Apply 新范围后同样将主数据区定位到已应用范围中心。
- 缩放时保持当前主数据区中心，避免视图跳回左端。

## 测试与验收

- Python 单元测试覆盖少于/等于/多于 25 个变异、边界锚点、缺失基因坐标和 VRN-B1 预期初始窗口。
- JavaScript 执行测试覆盖 initial current/pending 一致、Reset 恢复初始窗口、Clear 需 Apply、交叉数字输入预览与提交一致。
- 浏览器测试在 Edge Chromium 和 Firefox 中确认：首次只显示 25 个变异列；50% 缩放不改变范围且主视图区保持满宽；Apply 后定位正确；无页面脚本错误。
- 重跑 VRN-B1 robust discovery，确认 top haplotype、分数、样本数和 837 bp 插入事后匹配结论均未改变。

## 范围外事项

本次不修改 robust discovery 打分、单倍型划分、表型分析、文献位点验证或数据源。
